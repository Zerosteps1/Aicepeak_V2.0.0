# ADR-0007: Global factory CLI for daily maintainer work

- Status: Accepted by the maintainer on 2026-11-01 ([FACTORY-007](../work/FACTORY-007.md)); delivered locally outside the factory pipeline (decision 9). Decision 8 is superseded by [ADR-0009](0009-issues-as-work-orders.md); the [amendments of 2026-11-08](#amendments-2026-11-08) describe the current commands.
- Date: 2026-11-01
- Deciders: Felix (`ftrutschnig`)
- Related: [factory command reference](../factory-cli.md), [way of working](../way-of-working.md), [clients](../../factory/clients.md), [ADR-0005](0005-maintainer-local-senior-review.md)

## Context

Daily factory work needed two hand-managed clones, `cd` between them, long `session.py` and `clients.py` invocations, manual patch application and manual edits of the `factory-task` status. Activating two work orders took three PRs because the status was first forgotten and then mistyped. The maintainers want one installed command that does this work from any directory without weakening the trust boundary: trusted code only from clean current `main`, an isolated author without credentials, a binding review on a maintainer device and a human merge.

## Decision

1. **A global shim runs only the control checkout.** The installer writes `~/.local/bin/factory`, outside every checkout, which runs the configured control checkout's `tools/factory/cli/factory.py` with the Python found at install time (`-I -S -B`). `factory.py` exits before any other action if it is not that copy. Before every command it takes the control lock, verifies the control checkout (configured repository, `main`, clean including untracked and ignored files), fetches `main` over https and fast-forwards it, imports all its modules while still holding the lock and restarts itself when the verified code changed. It never resets or deletes files in the control checkout.
2. **Background runs use a pinned export.** `start`, `fix` and `hotfix` run in the background from an export of exactly the verified control commit inside the run folder, so later control updates never change a running job. Ctrl-C only detaches; `factory continue` reattaches.
3. **`session.py` sees only disposable checkouts.** Every `session.py` and `doctor.py` call runs from a disposable checkout of the `main` commit it works against, and receives the candidate as a disposable snapshot of the committed state. Both are written byte-exact from Git objects (no clone, checkout filter, hook or attribute conversion). Candidate files never execute on the host.
4. **Git and the candidate are hardened.** Every Git call runs without hooks, fsmonitor, global or system configuration, attribute files, replace objects, lazy fetches or submodule recursion, and reaches GitHub only over https with the maintainer's `gh` credential helper. The candidate must be a plain clone separate from the control checkout, and its local Git configuration may contain only an allowlist of keys.
5. **Author keys stay with the launcher child.** `ANTHROPIC_API_KEY` and `CONTEXT7_API_KEY` come from the environment or from the login keychain items `aicepeak-factory-anthropic-api-key` and `aicepeak-factory-context7-api-key` (exported variables win). They are handed to the background runner through a pipe and placed only in the environment of the `clients.py run` child, never in a file, log or argument.
6. **Docker run labels make cancel complete.** `clients.py run` accepts `--label`, set on every container, network and volume of a run, plus `--read-only` for reviews and `--events-file` for a credential-redacted line per tool call. `factory cancel` terminates the run and removes everything with its label; on SIGTERM the launcher removes its own resources.
7. **`hotfix` pushes only behind a gate.** It pushes automatically only changes inside the work order's `allowed_paths` and outside `protected_paths`, without binary, symlink or submodule entries, with a passing preflight on exactly the pushed result, an unchanged `main` and an unchanged remote branch, and never with force. Otherwise it behaves like `fix` and leaves the result to the maintainer. This mirrors the rule that control paths are never auto-corrected.
8. **FACTORY-005 and FACTORY-006 are superseded and removed.** FACTORY-007 replaces the managed control checkout (FACTORY-005) and the idea of GitHub issues as work orders (FACTORY-006); both files are deleted. Work orders remain files in `docs/work/`, created by `factory issue` and activated by `factory submit workorders`.
9. **Delivered locally outside the factory pipeline.** By maintainer decision of 2026-11-01, FACTORY-007 was implemented locally without the isolated launcher, a prior work-order PR or `session.py submit`. The isolated author cannot write `tools/factory/` anyway. The maintainer reviews the diff and decides how it reaches `main`; live acceptance on a maintainer device is recorded in [factory/evidence.md](../../factory/evidence.md) after the merge.

## Consequences

- Maintainers install once and use `factory` for issuing, activating, implementing, fixing, reviewing, submitting, watching and merging. The underlying `session.py` and `clients.py` commands stay available for troubleshooting ([without the CLI](../factory-cli.md#without-the-cli)).
- The gate, the binding review, the GitHub workflows, models, limits, rulesets and required checks are unchanged. The launcher changes are opt-in; without the new flags its arguments and result parsing are unchanged, so the CI correction path is unaffected.
- One local run stays within `max_cost_usd` across its model steps and each step within `max_run_cost_usd`. The displayed amounts are Claude-reported estimates; the broker's caps stay authoritative.
- Changes to control paths (`tools/factory/`, `factory/`, `.agents/`, …) remain manual, protected changes: the isolated author cannot write them, `factory start` refuses work orders that lie entirely inside them, and `factory review` lists them as not reviewed.
- Residual risks: whoever can write the maintainer's home directory can change the shim, the device configuration, the state folder or the control checkout, as before. Background runs and watchers pause during system sleep; `caffeinate` prevents only idle sleep. Cost figures are estimates. The CLI is macOS-first (keychain, `caffeinate`, `~/.zshrc`); elsewhere the author keys must be exported.

## Amendments (2026-11-08)

The CLI cleanup of 2026-11-08 (`factory` 0.5.0) describes the current state; where it differs, it replaces the decisions above.

- **Work orders are GitHub issues** ([ADR-0009](0009-issues-as-work-orders.md), which supersedes decision 8). An issue is opened on GitHub from the "Factory work order" template and approved with `/review` and `/accept`; `factory issue`, `factory submit workorders` and the replaced `factory sync` are removed. The only work order that stays a file is the device smoke (`docs/work/FACTORY-SMOKE.md`), submitted with `factory submit` from its own branch.
- **One grammar.** Every command that takes a work order names it `workorder <issue>` (`factory start|continue|stop|cancel|fix|review workorder 57`); texts name it `#57`. `continue`, `stop` and `cancel` name the run of a hotfix without a work order `hotfix`. `factory submit` takes the work order from the branch name only; `--workorder`, `--draft`, `--context` and `--pr` are removed.
- **One work order is one branch and one PR.** The branch is named as GitHub names an issue's branch, `57-<issue title>`; `factory start` continues it and `factory fix` lands on its open PR (or the branch before the PR exists). There are no `-<k>` or `-fix-<k>` branches any more; follow-up work is a new work order.
- **`hotfix` may run without a work order** (`factory hotfix "<problem>"`): it fixes the problem on a new branch `hotfix/<date>-<words>` from the default branch, without a preflight, and pushes that branch behind its push gate (no protected or guarded path, no binary, symlink or submodule entry) without opening a PR. With a work order it works as in decision 7, and its PR names the work order and says `Closes #57`.
- **Commit titles** default to `<issue title> #57`: the issue number last, so that no editor takes the line for a comment.
- **`session.py response` is removed**; questions about a PR are asked in a manual Claude session. `factory watch` keeps the Mac from idle-sleeping like a run, and `factory doctor` takes every tool version from `factory/package.json`.
