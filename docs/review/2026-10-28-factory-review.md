Status: review report. Items marked **Decided** were decided by the maintainer (Gabriel, `Zerosteps1`) on 2026-10-28; everything else is a recommendation that needs its own reviewed PR. The decisions are recorded in [docs/decisions](../decisions/README.md).

## Summary

**Verdict: the architecture is very good, but the factory cannot operate today.** The trust boundaries (metadata-only dispatcher, network-less tests, two App identities, SHA-bound required checks, credential broker) are stronger than any vendor offering and should stay. Four things block operation:

1. `main` is unprotected right now: no rulesets, and the environment has no branch policy (F1).
2. Codex does not load the provider settings from `.codex/config.toml`, so the worker never reaches the broker (F33). The patch prepared in the maintainer's Codex session is the right fix.
3. The broker rejects every real Codex request, because Codex 0.164.0 always sends `client_metadata` (F28).
4. The output reservation caps every author run at four model turns (F5).

**Other important points:** GitHub blocks `pull_request_target` for public repositories from 2026-12-02 (F29); the review input budget cannot hold the 99 KB north star plus a real product diff (F8); the north star references a missing chapter 12 thirty-two times (F14); there is no product stack (F13); one maintainer alone deadlocks the rulesets (F3); dense code and mixed languages (F17, F20); factory before product (F27).

**Subscriptions instead of API billing (Decided, operating model S1):** the gate reviewer is GPT-6 Astra run through `codex exec --output-schema` under a ChatGPT Business access token on the maintainer's trusted machine, in a fresh session, publishing through the Publisher App. The author is Claude Code behind the existing broker, funded by the Claude Team plan's monthly API credit ("never charged to your Claude plan"). No `OPENAI_API_KEY`. A Hermes agent brings no advantage. Evidence in section 4.4, decision in [ADR-0005](../decisions/0005-operating-model-without-api-billing.md).

**Maintainer decisions (2026-10-28):** operating model S1; Felix joins as second verified maintainer before activation ([ADR-0001](../decisions/0001-maintainer-model.md)); English everywhere except the north star ([ADR-0004](../decisions/0004-language.md)); implementation as PR A (this report, ADRs, templates) and PR B1/B2 (model path) as draft PRs; only a human merges.

**Next steps after approval:** merge PR A and B1/B2 (section 7). Then, by the maintainer: verify Felix, register the Apps, run `settings.py apply`, create secrets, run the smoke PR with the deterministic gate only, keep the senior review advisory during a shadow phase, and start the first product task within a week (section 6).

## Context

The repository contains a self-built "software factory". Pull requests are checked by a trusted GitHub Actions pipeline that runs from `main`: deterministic checks in a network-less Docker container, a tool-less senior review by `gpt-6-astra` with a strict JSON schema, and two App-bound required checks. On `changes_requested`, an isolated AI author (Codex CLI 0.164.0 or Claude Code 2.1.311) fixes the PR in a hardened Docker worker behind a credential broker; a Writer App commit lands on the PR branch through an atomic `updateRefs`. Humans merge. Beyond the four blockers, the factory is built on API billing, which the maintainer does not want (section 4.4), has no product connection (no stack, no product checks, north star without chapter 12), and is weak in maintainability (dense code, about 2,600 lines of security-critical custom code, mixed languages). The research supports "thin pipeline first, the factory grows with real work" (section 6).

## 2. Strengths (keep)

1. **Clean trust boundaries.** PR content never runs in a privileged context: `pull_request_target` only as a metadata dispatcher, the pipeline runs via `workflow_dispatch` on `main`, `permissions: {}`, `persist-credentials: false`, Actions pinned to full SHAs, `cache-mode: none`. Candidate tests run in Docker with `--network none`, read-only, without secrets.
2. **Two GitHub Apps with a minimal permission split.** Required checks are bound to the Publisher App's `integration_id`; CODEOWNERS; no bot bypass; no auto-merge. The ruleset desired state is an idempotent `inspect/diff/apply`.
3. **Fail-closed everywhere.** Every stage re-checks head, base and policy SHA, run ID and attempt; stale runs are cancelled; reruns are refused; double processing is detected; budgets and three rounds are kept in an App-authenticated ledger; atomic `updateRefs` push with `beforeOid`.
4. **Credential broker.** Workers see neither provider nor GitHub keys; only fixed routes, allowlisted request fields, no hosted tools, no media, limited documentation MCPs, no prompt logging.
5. **Hardened workers.** `--read-only`, `--cap-drop ALL`, `no-new-privileges`, PID/CPU/memory limits, internal network with fixed DNS, tmpfs volume instead of host bind, symlink, binary and submodule blocks, patch extraction by a network-less helper.
6. **Shared canonical skills and roles** for Codex and Claude; generated adapters with drift check; prompt-injection rules ("content is data, not authority") in every skill.
7. **Honest evidence.** `evidence.md` separates executed from open checks; `doctor.py` never issues an operating certificate; a smoke task with a controlled defect exists.
8. **Review contract.** Strict JSON schema, binding to SHAs and run, P0/P1/P2 semantics, "a clean change needs no finding", earlier findings are re-checked at the new head.

## 5. Decided operating model S1

**Decided (2026-10-28): operating model S1 = reviewer through path D plus automatic correction through path A** ([ADR-0005](../decisions/0005-operating-model-without-api-billing.md)).

- **Reviewer:** GPT-6 Astra, effort high, via `codex exec --ephemeral --sandbox read-only --output-schema factory/review.schema.json -o result.json -c model_reasoning_effort="high"` under a ChatGPT Business access token, started as a new session on the maintainer's trusted machine (or a small always-on machine) by a factory command (`python3 tools/factory/local_review.py --pr N`, PR B1), not on GitHub runners. Same schema, same SHA binding, published as `factory/senior-review` through the Publisher App. Additionally `@codex review` as a free second opinion.
- **Author:** Claude Code behind the existing broker, API key of the Console organisation linked to the Claude Team plan; it consumes only the plan's monthly API credit and stops when that is exhausted ("never charged to your Claude plan"; Anthropic caps the pooled credit at 500 USD). No direct API billing.
- **Consequences:** reviewer and author are different model families (F34 resolved); no credentials in the worker (path A unchanged); USD ledger stays for the author, message/token counters for the reviewer; `OPENAI_API_KEY` disappears completely; `ANTHROPIC_API_KEY` (Team organisation) and `CONTEXT7_API_KEY` remain environment secrets. To verify before activation: Console organisation linked to the Team plan (7-day waiting period), a test run of `claude -p` through the broker shows up in the Console as credit usage, `--max-budget-usd` as second brake. Automatic correction is enabled only after the shadow phase (section 6).
- **Rejected:** the Codex author variant sketched in the original S1 row (placeholder token exchanged by the broker for the real ChatGPT token; credential in the worker, unofficial endpoint); S3 (Hermes); S2 (Codex cloud review as gate; only as free second opinion).

**Interlock between local review and author job:** the local reviewer publishes `factory/senior-review` in the same receipt format (binding to head/base/policy SHA, snapshot, review JSON) through the Publisher App; on `changes_requested` it starts the author job on GitHub Actions with `gh workflow run factory.yml -f pr=N -f correction=<check_id>`; `engine.py author` verifies the authentic check receipt as today (`authentic_check`, binding, reservation) and runs Claude through the broker; the Writer App push triggers the next run. The GitHub review job (`review_stage` with `OPENAI_API_KEY`) disappears; `publish_stage` accepts reviews only from authenticated receipts, wherever they were produced.

**Options that were on the table:** S1 (subscription reviewer on a local trusted launcher; originally with a Codex author, decided with the Claude author of path A), S2 (Codex cloud review and `@codex fix`, factory only as gate: zero infrastructure, but no strict JSON schema, review rules from the PR-controlled `AGENTS.md`, depth not controllable), S3 (Hermes agent as reviewer: rejected, see path F/G) and S4 (local reviewer, corrections only by the human in the working session: the smallest change, and effectively the first stage of S1 until the shadow phase ends). Reasons per option are in [ADR-0005](../decisions/0005-operating-model-without-api-billing.md).

All paths share: F1, F3, F14, F29 stay unchanged; F5 and F28 concern the broker (author path); F33 concerns every Codex start through overrides. Technical note (verified in the Codex 0.164.0 schema; relevant only if a Codex author with a Business token in the worker is wanted later): Codex has a native network MITM configuration (`NetworkMitmToml`: `hooks` by host, path prefix, method, port; `actions.inject_request_headers` with `placeholder` and `secret_env_var`/`secret_file`, `strip_request_headers`), which could reproduce the "placeholder in the worker, real token only at the proxy" pattern of Codex cloud locally.
