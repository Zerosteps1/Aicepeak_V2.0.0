# Isolated native clients

The shared sources are the four `.agents/skills/*/SKILL.md` files and `.agents/roles.json`. Codex discovers the shared skills directly. Claude gets generated native copies under `.claude/skills/`; `CLAUDE.md` imports `AGENTS.md`. Generated Codex roles use the **0.164.0** schema's `agents.<name>.config_file`.

Codex applies only `model`, `model_reasoning_effort`, `developer_instructions`, `features` and `skills` from a role file and discards `sandbox_mode`. The generated Codex role `factory_senior_reviewer` is therefore **not** read-only: it inherits the session sandbox, which is `workspace-write` in the author container (review finding F26). The generator no longer writes the ignored key. The Claude role `factory-local-reviewer` is limited by its tool list (Read, Glob, Grep, Skill and the documentation MCP tools). Both local reviewer roles are advisory and never impersonate the independent senior review gate, which is [`local_review.py`](#senior-reviewer-maintainer-local).

```sh
python3 tools/factory/clients.py sync --root .
python3 tools/factory/clients.py check --root .
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tools/factory/tests
```

`check` rejects adapter drift, extra skill/config files and symlinks. Changing a canonical skill requires regeneration and review. Protected factory changes require the manual proposal path below.

## Build and run

Do not start plain `codex` in this checkout. The required MCP endpoints use the isolated broker's Docker hostname and a disposable `FACTORY_PROXY_TOKEN`, generated by `launch`/`run`; it is not a personal API key. A direct host start cannot initialize those endpoints. Do not invent a token, disable required servers or move the broker settings into your personal configuration to bypass the launcher.

Codex filters provider selection and definitions out of project-local configuration. The trusted launcher supplies these settings as CLI overrides for interactive workers, unattended workers and native smoke discovery. Project adapters retain skills, roles and required MCP declarations. Before native startup the launcher also creates only the `/work` trust entry in the fresh container-only Codex home. Codex evaluates project trust before session CLI overrides, so a CLI trust flag alone does not load the project MCPs and roles. The author launcher's headless execution reads this disposable user layer; it does not use `--ignore-user-config`. No host user state is mounted. Managed requirements still apply; provider routing neither reads nor changes personal configuration. The Codex author launcher needs `OPENAI_API_KEY`; a regular Codex/ChatGPT login or the senior reviewer's access token does not replace it.

Build only from the trusted checkout. Both CLI versions are pinned; runtime resolves the local image to its immutable SHA256 ID before starting containers.

```sh
docker build -f factory/Dockerfile \
  -t aicepeak-factory-clients:codex-0.164.0-claude-2.1.311 factory
python3 tools/factory/clients.py smoke --root .
python3 tools/factory/clients.py launch --root . --runner claude
```

The unattended interface is:

```sh
python3 tools/factory/clients.py run \
  --root /path/to/candidate --policy-root /path/to/trusted-base \
  --runner claude --prompt-file /path/to/task.txt \
  --output-patch /path/to/changes.patch
```

`run` returns JSON with `patch`, its SHA256, `report`, `report_truncated` and the author cost reservation ceiling. The report is `changes.patch.report.txt`, valid UTF-8 below 8 KiB. It contains only final user-facing text, including disagreements or reasons for an empty patch. Raw transcripts and reasoning events are discarded. The orchestrator independently validates the patch and report before publishing either. `launch` is interactive and returns a patch artifact without changing the original checkout.

Provide the author credentials only to the trusted launcher environment through the execution platform's secret facility: `ANTHROPIC_API_KEY` for the Claude author, plus `CONTEXT7_API_KEY`. `OPENAI_API_KEY` is needed only for the optional, API-billed `--runner codex` launcher; the factory pipeline and the senior reviewer do not use it. The GitHub author job no longer receives `OPENAI_API_KEY`, so automatic correction there works only with the Claude runner. Do not put values in repository files or CLI arguments. The launcher passes only the selected provider secret to the separate broker, and only a disposable job credential to workers. It does not read personal configs or credential stores. `FACTORY_DOCKER_HOST` can explicitly select a Docker endpoint; the launcher uses an empty Docker config directory.

The documented Claude author configuration is `author_models.claude: "claude-sonnet-5-5"` with `author_pricing_usd_per_million.claude: {"input": 2, "output": 10}` (USD per million tokens, verified 2026-10-27). Anthropic documents Claude Code >=2.1.284 for this model; the pinned 2.1.311 meets that requirement. The broker's doubled input reservation also covers the documented 1-hour cache-write price of $4. This is a documented-compatible configuration, not an authenticated runtime result. Missing model/prices still fail closed. Each runner needs its own `author_pricing_usd_per_million` entry; there is no fallback to reviewer pricing, because the senior reviewer runs on a subscription seat and has no USD price. Every author run is bounded by `limits.max_run_cost_usd` (fallback `max_cost_usd`); the orchestrator must reserve this ceiling against the whole task's budget.

## Boundary

1. Copy only bounded regular candidate files, excluding Git metadata, nested agent configuration, obvious credential files and dependency caches. Overlay trusted instructions, factory code and native configuration.
2. Initialize a fresh Git baseline with host/global hooks, filters and configuration disabled. Linked-worktree `.git` pointers are never followed.
3. Seed a 512 MiB Docker tmpfs volume through a trusted network-disabled helper. The model never gets a writable host bind mount.
4. Start a separate credential broker with fixed OpenAI, Anthropic and Context7 destinations. The worker has only an internal Docker network, restricted DNS, a read-only root filesystem, read-only trusted overlays and Git metadata, no capabilities, no Docker socket, and no host home or credentials. CPU, memory, PID, time and output limits apply.
5. Start a fresh native session. Codex excludes personal configuration and prior sessions, seeds only disposable project trust, and disables plugins and memory; sanitized project files contain no hooks. Claude selects project settings, explicit MCP, no persistence and no auto-memory or non-managed hooks. Native shell permissions operate inside the outer Docker boundary.
6. A trusted network-disabled helper checks output files before extracting the patch. The original candidate is not modified; the launcher never commits a result, pushes, posts a comment or merges.

Organization requirements must be provisioned by the administrator in the approved execution image: Codex `/etc/codex/requirements.toml` (and any legacy `/etc/codex/managed_config.toml`), and Claude `/etc/claude-code/managed-settings.json` plus required managed hooks. The launcher neither reads host policy/personal files nor removes image policy. Fresh user directories and project-only settings are not an exemption from managed requirements. The author launcher no longer uses `--ignore-rules`; no rule exclusion is needed in this sanitized environment. Mandatory restrictions continue to constrain native execution. If they conflict with the reviewed container permissions or provider, execution must stop for administrator review; do not weaken policy or use a stock image to evade it. Cloud/account policy that cannot be delivered or checked in this isolated runtime is an activation blocker for organizations requiring it.

## Protected factory changes

The read-only control overlays deliberately prevent authors from editing `.agents`, native adapters, `AGENTS.md`, `CLAUDE.md`, `factory/` or `tools/factory/`, even when a task requests a factory change. There is no runtime unlock flag or automatic control remediation. The author can return a concise proposal and evidence in its final report. A maintainer then creates a separate branch in an ordinary checkout, applies the proposed control change, regenerates adapters, runs `check` and the trusted test harness against that candidate, and submits a manually managed PR for the required human/security review. Existing trusted-base gates remain in force. After acceptance, an authorized maintainer builds and approves the replacement execution image and activates the new trusted controls. Dependency update PRs follow this same path.

The broker accepts only its selected model and fixed routes; denies hosted tools, media, remote prompt/state/container references, model fallbacks and premium inference modes; and reserves a conservative text-input/output budget before every request. The hosted-tool check covers the top-level `tools` field and the tools inside `additional_tools` input items, which is how Codex 0.164.0 announces its tools. Reservations are not refunded, so a job can stop earlier than its actual bill would imply. Token and cost controls depend on configured prices; review them when changing models. Unknown provider request fields fail closed and require a reviewed compatibility update. The Codex field allowlist includes `client_metadata` (Codex 0.164.0 always sends trace keys there), `stream_options` and `prompt_cache_options`; `tools/factory/tests/fixtures/codex-0.164.0-request.json` is the captured request body. Every CLI update must capture a real request again and re-check the allowlist against it before the update is accepted.

Both native clients include required documentation servers. Context7 (`https://mcp.context7.com/mcp`) permits only initialization/ping/discovery and `resolve-library-id`/`query-docs`. OpenAI Docs (`https://developers.openai.com/mcp`) permits `search_openai_docs`, `list_openai_docs`, and `fetch_openai_doc` plus the same protocol setup. Fetches accept only HTTPS public documentation URLs on developers.openai.com, platform.openai.com/docs/ or learn.chatgpt.com/docs/. Results are capped at 20 per call, and both servers share a 64-request job cap. Native configs authenticate to the broker with the disposable job token; OpenAI Docs receives no upstream credential. Before inference, generic MCP preflight initializes and discovers each required tool set. This preflight is separate from native client discovery and does not claim native tool execution succeeded.

## Senior reviewer (maintainer-local)

`tools/factory/local_review.py` is the senior review gate (ADR-0005). It runs only on the maintainer's trusted Mac and never on GitHub-hosted runners: OpenAI intends ChatGPT workspace access tokens for trusted machines and private runners, and this repository is public. It reviews the snapshot that the pipeline left in a pending `factory/senior-review` check and publishes the verdict in the existing receipt format through the publisher App. Usage is described in the [README](../README.md#senior-review-on-the-maintainers-mac).

Preconditions, checked before any model call:

- The pending check belongs to the publisher App and the current PR head, and its `awaiting_review` receipt binds the check ID, external ID, PR and head. The receipt's deterministic tests passed.
- The script's own checkout is clean and exactly at the receipt's policy SHA, because the instructions (`factory/policy.md`) and `factory/review.schema.json` come from it.
- Fewer than `limits.max_reviews_per_pr` reviews were already published for the PR. Reviews consume the maintainer's Codex seat window, which is shared with interactive use; there is no USD reservation.
- Head, base, policy, handoff and human feedback still match the snapshot, and the complete prompt fits `limits.review_input_bytes`.

Session design (`codex exec` from pinned `codex-cli 0.164.0`; any other version stops the run):

- Fresh temporary `CODEX_HOME` and `HOME` (with `TMPDIR` inside), deleted after the run: no personal configuration, instructions, memories or sessions. `--ignore-user-config`, `--ignore-rules`, `--strict-config` and `--ephemeral`; `cli_auth_credentials_store="ephemeral"` so the token is never saved as a login; `history.persistence="none"`; analytics, feedback and update checks off.
- The child environment contains only `PATH`, `HOME`, `CODEX_HOME`, `TMPDIR` and `CODEX_ACCESS_TOKEN`. `CODEX_ACCESS_TOKEN` is the only credential; the publisher key stays in the parent process. The token is redacted from any error output.
- Empty working directory (`--cd` to an empty temporary directory, `--skip-git-repo-check`, `project_doc_max_bytes=0`): no repository file is on disk for the model. The review material arrives on stdin and the instructions as `developer_instructions`.
- `--sandbox read-only`, `approval_policy="never"`, `web_search="disabled"`, model `gpt-6-astra` with `model_reasoning_effort="high"`.
- `--output-schema factory/review.schema.json` with `--output-last-message`. The result is validated with `contracts.validate_review` against the snapshot binding before publication.

**Verified tool-surface finding (Codex 0.164.0).** Feature flags alone do not make `codex exec` tool-less. Codex announces tools to the model in an `additional_tools` input item, not in the top-level `tools` field. With only the tool features disabled, the session still offered the code-mode `exec` tool with nested `exec_command`, `apply_patch` and `view_image`, plus the multi-agent tools such as `spawn_agent`. Because the review summary is posted publicly on the PR, any file the model can read could leak. The countermeasures fail closed:

1. A generated model catalog (`model_catalog_json`), taken from `codex debug models`, that contains only `gpt-6-astra` with `shell_type="disabled"`, `apply_patch_tool_type=null` and no experimental tools.
2. `agents.enabled=false` and every tool- or state-loading feature disabled, including `code_mode_host` (full list: `TOOL_FEATURES` in `local_review.py`).
3. An offline preflight before every run: `codex debug prompt-input` with the same overrides. Top-level tools must be a subset of `exec`, `wait` and `request_user_input`; tools nested in `exec` must be a subset of the MCP resource helpers `list_mcp_resources`, `list_mcp_resource_templates` and `read_mcp_resource`, and no MCP server is configured. What remains is the JavaScript isolate without file system or network, whose host is disabled.
4. An event-stream check: any item other than `agent_message`, `reasoning`, `todo_list` or `error`, including unknown types, discards the review.

A Codex update can change this surface. It needs a reviewed change of the pinned version, the allowlists and their tests, based on a new `prompt-input` capture, before reviews run again.

Publication re-checks freshness first; a stale snapshot only gets `failure` for its old SHA and the next pipeline run asks again. Otherwise the check is completed with the gate conclusion, and the receipt records the reviewer (`host: maintainer-local`, client, model, effort, `auth: chatgpt-workspace-access-token`, thread ID, turns and token usage) instead of a USD amount. The PR comment marks the review as advisory while `factory/senior-review` is not a required check. On `changes_requested` without control changes, and only when `automatic_correction` is `true`, the maintainer's GitHub CLI dispatches `gh workflow run factory.yml -f pr=N -f correction=<check_id>` (suppressed by `--no-dispatch`). Otherwise a non-`pass` outcome labels the PR `needs-author-action`, and a `pass` removes that label.

Credentials come from the macOS login keychain items `aicepeak-factory-codex-access-token` and `aicepeak-factory-publisher-key` (PEM stored base64-encoded); the environment variables `CODEX_ACCESS_TOKEN` and `FACTORY_PUBLISHER_APP_PRIVATE_KEY` take precedence over them. `local_review.py --smoke` runs the same version, catalog and tool-surface checks plus one tiny schema-bound turn, without GitHub access.

## Verification status and limits

The implementation has local regression tests for configuration drift, inherited policy removal, linked Git pointers, symlink escape, patch extraction, secret environment separation, fresh-session flags, report filtering, route/model restrictions, remote-source rejection, budget exhaustion and the reviewer's tool-less session, receipts and publication.

`smoke` creates a harmless host canary outside the mounted project and a project symlink to it. Inside the secret-free, network-disabled container it requires a successful project read, rejected direct/symlink canary reads, and rejected write access to trusted instructions. It asks the real Codex app server for `skills/list`, `config/read` and `configRequirements/read`, requiring the four canonical skill paths and reviewed provider/role/MCP configuration without starting a model turn. It runs Claude's native plugin validation on skill/agent directories and `doctor`; Claude authenticated startup discovery remains explicitly unverified. These checks establish only the exercised boundary, not a proof against every container escape. Tests use `FACTORY_CANDIDATE` to import candidate implementation and canonical sources under the trusted base harness, including `python -I`.

**Live validation was blocked in the setup environment (2026-10-27):** the Docker socket returned permission denied and no provider/Context7 credentials were available. No image build, container execution, native model call or native MCP connection has passed so far. `smoke` reports this as `blocked`, never as success. Connected Context7 tools were successfully exercised during research; that does not prove the isolated clients' connection. The local reviewer evidence for PR B1 is in [evidence](evidence.md).

`package.json` and `package-lock.json` are standard npm manifests for dependency-update tooling. The complete npm v3 lock includes both CLIs and all 14 optional native packages with vendor-published tarball SHA512 integrity; provenance is recorded in this document and `evidence.md`. The Dockerfile uses `npm ci`; no checksums are invented. Version-update PRs must also update the CLI assertions, image tag and reviewed compatibility tests; updates do not activate themselves. The base image is pinned to the multi-architecture digest published by the [official Node Docker Hub metadata](https://hub.docker.com/v2/repositories/library/node/tags/22.21.1-bookworm-slim), verified 2026-10-27. Apt still resolves OS packages at build time; a trusted release build must record the package inventory and resulting image ID for archival reproducibility. Workers use the selected local image ID. Keep the strict broker allowlist and required MCP initialization under a real authenticated smoke test before activation.

The second issue also affected the isolated launcher: its effective configuration had no factory provider. Credential-free native `config/read` probes with Codex 0.164.0 exposed the missing provider and a disabled project layer: CLI trust did not activate that layer. After correction, the interactive, unattended and discovery configuration probes selected the factory endpoint and disposable credential reference, loaded both required MCP declarations and both native roles, and reported no disabled project layer. No model turn or live MCP connection was started. CLI-level broker configuration and disposable trust initialization are covered by regression tests; container/network/model execution remains a separate acceptance step.
